# AI Provider 配置与模型选择基础能力

## 目标

为脚手架增加可复用的 AI 接入基础：管理员统一配置模型服务和可用模型，登录用户从管理员允许的模型中选择默认模型，后续对话、Agent 和内容生成场景通过同一套服务端入口调用模型。

## 已确认事实

- 项目是 pnpm + Turborepo 的 TypeScript monorepo，包含 `apps/admin`、`apps/web`、`apps/api` 和 `packages/contracts`。
- `apps/api` 使用 Hono、Drizzle 和 SQLite，数据库请求按 `route -> service -> repository` 组织。
- `apps/admin` 已有登录态、权限控制、功能路由和菜单注册机制。
- 管理员需要配置 Provider、API Key、可用模型和全局默认模型。
- 用户只能从管理员启用的模型中选择。
- 候选模型调用库为 `@earendil-works/pi-ai`；初步调研确认它支持多 Provider、流式输出、工具调用、自定义兼容端点和可注入凭据存储。
- 用户已认可“业务配置层与 AI 运行时适配层分离”的候选架构方向。

## 需求

- 管理员可以查看、创建、修改、启用和停用全局 AI Provider 配置。
- Provider 配置按 `@earendil-works/pi-ai` 当前版本的内置 Provider 能力展示对应认证字段，不能假定所有 Provider 都只有 API Key。
- 第一阶段覆盖当前固定版本提供的全部内置 Provider，包括普通 API Key、OAuth、Amazon Bedrock 环境凭据和 Vertex ADC 等认证方式。
- Admin 管理 API Key 及可表单化的 Provider 字段；OAuth、AWS credential chain、Vertex ADC 和服务账号文件由 API 部署环境或运维流程配置，Admin 只展示认证状态和配置说明。
- 每个内置 Provider 只保留一份全局有效配置；更换 API Key 或端点通过更新、重新检查和重新启用完成，不支持多个同类 Provider 实例。
- 用户模型偏好放在现有登录后控制台的用户设置区域；全局 Provider 配置和模型白名单使用独立的管理员权限。
- API Key 只在服务端保存和使用；读取接口不得返回明文，日志不得记录明文。
- 模型目录以内置 `pi-ai` catalog 为来源，管理员从已认证 Provider 的目录中勾选白名单；支持动态目录的 Provider 额外提供刷新操作，不允许任意手工录入模型元数据。
- 登录用户只能查看管理员启用的模型，并可以保存自己的默认模型。
- 用户提交的模型标识必须由 API 再次校验，前端选择不能绕过白名单。
- 模型选择顺序暂定为：本次请求指定的有效模型、用户默认模型、全局默认模型。
- Admin AI 页面提供“模型测试”面板：用户选择已启用模型、输入单条提示词并查看流式回答。
- 第一阶段只覆盖 `Models` 文本/工具调用模型；`ImagesModels` 图像生成保留独立接口边界，不进入本期调用和配置页面。
- AI 调用库只在 `apps/api` 内使用；Admin、Web 和跨端 contracts 不依赖第三方 SDK 类型。
- 管理员接口与用户接口使用不同的请求和响应 DTO，用户接口不得包含 Provider 凭据或管理员字段。
- `@earendil-works/pi-ai` 必须由项目内部接口包装，避免第三方 `0.x` API 变化扩散到业务模块。

## 验收条件

- [ ] 具备管理员权限的账号可以维护当前固定 `pi-ai` 版本提供的全部内置 Provider；无权限账号收到明确的权限错误。
- [ ] 管理员可以更新已有 Provider 的凭据或参数；更新后旧凭据不再被请求使用，且不会产生第二个同类 Provider 实例。
- [ ] API Key、OAuth、Amazon Bedrock 环境凭据和 Vertex ADC 等认证方式具有与 Provider 能力对应的配置状态和操作入口。
- [ ] Admin 读取 Provider 配置时只能看到密钥掩码和“已配置”状态，无法通过接口获得 API Key、OAuth token 或云凭据明文。
- [ ] 对不能由 Admin 表单完成的认证，页面显示当前状态、所需部署配置和检查结果；认证完成后模型测试可以使用该 Provider。
- [ ] 管理员可以从已认证 Provider 的内置模型目录中维护白名单；动态目录 Provider 刷新后，旧白名单和默认模型的有效性得到重新校验。
- [ ] 管理员可以设置全局默认模型，API 会拒绝将停用或不存在的模型设为默认。
- [ ] 登录用户只能看到启用模型，并能保存或修改自己的默认模型。
- [ ] API 拒绝用户选择停用、不存在或不在白名单中的模型。
- [ ] AI 运行时能按“请求指定 -> 用户默认 -> 全局默认”选出有效模型；没有可用模型时返回稳定错误码。
- [ ] 登录用户可以在模型测试面板输入单条提示词，并收到所选模型的流式回答。
- [ ] 模型测试只能调用管理员启用的文本/工具调用模型，不创建会话或消息历史记录。
- [ ] 图像生成模型不会出现在本期文本模型目录和模型测试面板中。
- [ ] Provider 鉴权失败、上游超时或流式请求中断时，页面显示可理解且可重试的错误。
- [ ] 前端产物、API 响应和应用日志均不包含 API Key 明文。
- [ ] 第三方 AI SDK 仅由 `apps/api` 的内部适配层调用。
- [ ] 相关类型检查、Lint、Format、API 测试和构建命令通过。

## 暂不包含

- 用户自带 API Key。
- 自动故障切换和多 Provider 负载均衡。
- 付费、充值、账单和复杂额度系统。
- 未经管理员允许的任意 Provider 或模型调用。
- 正式聊天页、会话列表、消息历史和上下文恢复。
- Admin 页面直接发起 OAuth 登录、上传 Vertex 服务账号文件或录入 AWS credential chain 的原始凭据。
- 同一个内置 Provider 的多个并行配置、多个账号和多个自定义端点。
- 任意模型手工录入及自定义模型能力元数据。
- 图像生成、`ImagesModels` 配置和图像资源管理。

无。
