# 优化 Admin Agent 新增编辑技能工具选择交互

## Goal

优化 Admin Agent 新增/编辑抽屉中技能和工具的选择体验，让管理员能快速搜索、区分资源、确认已选内容，并在工具版本冲突时获得清晰反馈，同时保持现有 Agent 配置提交结构和 API 契约不变。

## Confirmed Facts

- 页面位于 `apps/admin/src/features/ai/pages/Agents.tsx`，新增和编辑共用一个 560px 宽的 Ant Design `Drawer`。
- 技能和工具当前使用 `Select mode="multiple"`，选项把名称、版本和描述拼进一行 label，长文本会影响扫描和已选项展示。
- 工具引用使用 `name + NUL + version` 作为 UI value，提交时还原为 `{ name, version }`。
- 同一个 Agent 不能同时选择同名不同版本的工具，当前在提交阶段拦截。
- Admin 已依赖 Ant Design 和 lucide-react，不需要新增选择器依赖。

## Requirements

- 技能和工具继续使用现有表单值与 API 数据结构，不改变接口契约。
- 将技能和工具的下拉选项改为可扫描的多行资源项：突出名称，辅助展示描述；工具同时明确展示版本，必要时展示 scope。
- 已选资源使用紧凑且可区分的标签展示，避免把完整描述堆进输入框；保留单项移除能力。
- 保留搜索能力，并确保搜索可以命中资源名称、版本和描述等关键信息。
- 在没有资源、资源加载中、资源加载失败时保持现有页面反馈，不阻塞其他字段展示。
- 保留新增、编辑回填、保存 pending、工具同名版本冲突校验等现有行为。
- 交互在抽屉窄屏和较长资源名称/描述下不能造成布局溢出或遮挡。

## Acceptance Criteria

- [ ] 技能下拉项能清楚区分名称和描述，工具下拉项能清楚区分名称与精确版本，并且已选项不显示完整长描述。
- [ ] 输入资源名称、工具版本或描述的关键词可以筛出对应选项。
- [ ] 新建时技能和工具默认为空；编辑已有 Agent 时已选资源正确回填并可单独移除。
- [ ] 选择两个同名不同版本工具后保存仍会阻止提交，并显示现有冲突提示。
- [ ] 资源加载状态、空列表、失败重试、保存 loading 和表单提交结果保持可见且行为正确。
- [ ] Admin 类型检查、Lint、格式检查和现有测试全部通过。

## Out of Scope

- 不新增第三方选择器依赖。
- 不调整 Agent API、contracts、数据库或工具版本冲突规则。
- 不改造 Agent 列表、权限逻辑和其他页面表单。

## Key Decisions

- 采用可折叠双栏资源选择器，不引入第三方依赖。
- 资源列表支持搜索和多选；选项分行展示名称、描述，工具额外展示精确版本和 scope。
- 已选资源区域默认折叠，仅展示已选数量和异常状态；展开后显示已选项并支持逐项移除。
- 技能和工具分别使用独立选择器，继续使用现有 `skillIds` 和 `toolRefs` 表单值。
