# 全面验证 Admin AI 模块

## Goal

验证管理后台 AI 模块从页面操作到 API 响应的实际行为，找出可复现的操作、接口和界面问题，并留下带步骤、请求路径、页面路径和结果的记录。

## 已确认事实

- Admin AI 路由位于 `apps/admin/src/features/ai/routes.tsx`，当前包含 7 个页面：
  - `/ai/chat`
  - `/ai/system-prompts`
  - `/ai/prompt-templates`
  - `/ai/skills`
  - `/ai/settings`
  - `/ai/providers`
  - `/ai/usage`
- 前端请求代码位于 `apps/admin/src/api/ai/`，页面通过 Hono RPC、统一 JSON 响应解包和 SSE 解析调用 API。
- API 路由位于 `apps/api/src/modules/ai/ai.route.ts`，覆盖 Provider、模型、个人默认模型、模型测试、会话、系统提示词、Prompt 模板、Skills 和用量审计。
- 页面和 API 已有单元测试及 API smoke tests，但此前归档任务记录了 Admin 页面未通过真实浏览器完成手测。
- Admin 开发端口为 `2333`，API 开发端口为 `7788`；用户要求用 `pnpm run dev` 启动工作区服务。
- API 本地环境默认开启 `AI_TEST_TOOLS_ENABLED=true`，真实模型调用仍取决于本地 Provider 配置和凭据。
- 本任务的验证范围包含中文和英文文案、受保护页面的权限入口、加载/空数据/失败状态、表单提交、删除确认、筛选分页、流式测试、会话发送/停止/重试和移动端布局。

## Requirements

### R-1 服务与基础访问

启动 `pnpm run dev`，确认 Admin、API 和已有健康检查可访问；记录启动失败、端口冲突、代理错误和跨域错误。

### R-2 页面与导航

逐页检查 7 个 AI 页面能打开，菜单、路由权限和页面标题一致；检查中文和英文切换后没有缺失 key、原始 key 或错误文案。

### R-3 管理页面操作

验证 Provider 配置、认证检查、启停、模型目录刷新、模型白名单、全局默认模型、系统提示词、Prompt 模板和 Skills 的读写操作；使用可回收的测试数据，不泄漏真实凭据。

### R-4 对话与模型测试

验证模型测试和 AI 会话的模型选择、空状态、快捷模板、输入快捷键、流式输出、停止、失败提示、重试、复制、删除和滚动行为。没有可用 Provider 时，页面应给出明确的不可用提示，而不是无响应。

### R-5 用量审计

验证用量列表的筛选、时间范围、分页、空数据、错误状态、详情抽屉和工具执行记录；确认列表和详情不显示不应返回的 Prompt、响应或凭据内容。

### R-6 API 调用与错误处理

使用浏览器网络请求和必要的直接 HTTP 请求核对页面实际调用的 method、路径、参数、响应 envelope、SSE 事件、401/403/4xx/5xx 处理以及 mutation 后的页面刷新。接口问题必须记录完整请求路径、状态码、错误 code 和复现步骤。

### R-7 验证记录

为每个页面和关键操作记录通过、失败或阻塞状态；每个缺陷包含严重程度、环境、复现步骤、实际结果、预期结果、相关文件或接口路径。若需要修改代码，补充对应自动化回归验证。

## Acceptance Criteria

- [x] `pnpm run dev` 启动结果已记录，Admin、API、健康检查和登录态访问结果明确。
- [x] 7 个 AI 页面在真实浏览器中逐页访问并记录结果。
- [x] 页面关键操作、API 调用、错误分支和响应式布局均有验证记录；未执行的 Provider 写操作、浏览器级 403 和部分失败注入已标明原因。
- [ ] 中文和英文页面没有缺失翻译或原始 key；Skills 描述必填文案仍缺失，已记录为 F-2。
- [x] 发现的每个问题都有可复现证据；未完成项目已标明验证范围和阻塞原因。
- [x] 本任务不包含产品代码修复，类型检查、Lint、格式检查和测试基线均已通过。

## Out of Scope

- 不新增 AI 产品能力，不改变 Provider、模型或权限设计。
- 不使用真实生产凭据，不向外部 Provider 发送未获授权的业务数据。
- 没有明确批准前，不把无法稳定复现的问题当作代码缺陷修改。
- 不提交 Git commit；提交前需单独取得用户确认。

## 已确定边界

- 本任务只做验证和记录，不修改产品代码。
- 发现可复现问题时，输出问题清单和复现证据，另行创建修复任务。
